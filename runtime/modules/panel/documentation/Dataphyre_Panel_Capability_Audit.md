# Dataphyre Panel Capability Audit

Audited: 2026-07-20

This document is the current source of truth for what Dataphyre Panel can
actually do today compared with a Filament-style target. It separates runtime
capabilities from demo-only proof points so we do not mistake a good showroom
for a complete framework contract.

## Status Legend

- `solid`: implemented as reusable Panel or Reactor framework code.
- `partial`: real framework exists, but the ergonomics, depth, persistence,
  testing, or production workflow is not yet Filament-level.
- `demo-only`: shown in the local `/debug` example, but not a complete reusable
  production framework guarantee.
- `missing`: not present as a first-party framework capability.

## Current Hardening Priorities

1. Keep every public claim tied to framework code and tests; the `/debug`
   showroom remains an exerciser, not a substitute for a reusable contract.
2. Use and certify the shared-SQL adapters and the Redis Streams realtime
   adapter where their deployment topology fits. Keep local atomic stores and
   reusable conformance packs as reference behavior, and add non-SQL queue or
   store transports only behind equally explicit authority and proof.
3. Keep browser, screenshot, axe, keyboard, focus, contrast, zoom, RTL,
   forced-color, reduced-motion, slow, and offline lanes inside source-bound
   evidence packs. Add platform-specific native AT adapters without relabelling
   browser proxies or manual declarations.
4. Expand optional editor integrations and deployment-specific tenant-directory,
	storage, and billing adapters without coupling core Panel to one JavaScript
	editor, ORM, broker, payment provider, or cloud.
5. Exercise the first-party signed registry operator and compatibility policy
   against application-selected remote transports and production package
   catalogs while keeping credentials, network clients, moderation, and hosted
   marketplace operations outside Panel core.
6. Promote CI-verified immutable API/cookbook/package releases to the selected
   documentation host/search index without weakening exact-tree,
   source-fingerprint, or deployment-credential boundaries.
